# 04 - UI

> Labels: **Decided** / **Proposed**.

## 1. Technology (Decided)

- **Next.js + TypeScript**, following **atomic design** (atoms, molecules, organisms, templates, pages).
- **SCSS** (CSS Modules, `*.module.scss`) is the styling language for what we write ourselves. (Decided)
- **MUI** and **Bootstrap**. How to use them together without style conflicts is not decided (see section 6).
- Pages live in the route group `src/app/(pages)/`; DTOs are declared in a `model` folder on both sides, the UI (`src/model`) and the BE (`src/server/model`). Details are in the application's `CODING_STANDARD.md`. (Decided)
- Every React hook lives in `src/hooks/`: `common/` for generic hooks and `<feature>/` for data hooks; atoms, molecules and organisms may use only the generic ones (they receive data as props). (Decided)
- The UI is in **English** in this phase; **all strings come from locale files** so Vietnamese can be added later. A language switcher is not needed yet. (Language switcher: an inference, not confirmed.)
- The i18n library is not chosen (for example `next-intl`).

## 2. Pages (Proposed)

| Page | Content |
|---|---|
| Login | Username + password form; errors shown by error code |
| Home | The user's projects; a button to create a project |
| Project | Documents, prompt, threads/chat, members |

The Project page contains:
- **Documents**: a list of sources with status (processing, ready, failed); file upload; add a YouTube video; delete (with confirmation); a bar showing used size out of 100MB.
- **Prompt**: an editor for the shared prompt; every member can edit it.
- **Chat**: the user's thread list; a button to create a thread; a conversation area that shows tokens as they arrive; delete own threads.
- **Members**: the member list; the owner adds by username and removes; a member has a Leave button; the owner has no Leave button; the owner has a delete-project button.

## 3. Behavior

- One tab opens **one SSE stream** for the whole user, not one per project. (Decided)
- Delete actions (document, thread, project, remove member) need a **confirmation step**. (Decided for deleting documents; the rest proposed)
- The UI hides or disables features by role, but the **server always checks permissions**. (Proposed)
- Server errors are translated by `code` from the `ApiResponse` envelope; validation errors use `errors[].field` to show messages at the matching input. (Decided)
- Messages from a user who has left the project still appear in their thread; threads stay attached to the user. (Decided)

## 4. AI answers

- Shown **progressively, token by token**. (Decided)
- **No source citations.** (Decided)
- In the language of the question. (Decided)
- When the connection drops mid-answer: reload the saved answer or catch up with `Last-Event-ID`. (Proposed)

## 5. UI code conventions (Direction decided)

- Structure follows atomic design; the application's coding standard has two parts: **UI** and **server (BE)**.
- Rules: no hard-coded display strings; every API call goes through one shared layer that understands the `ApiResponse` envelope.

## 6. Still open

- MUI + Bootstrap: whether Bootstrap is for grid/utilities or for components; rules to avoid style conflicts.
- The i18n library. Data is fetched with the built-in `fetch` through `lib/apiClient`; **TanStack Query is not used** (Decided).
- Visual design (colors, layout) has not been discussed.
